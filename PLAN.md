# Rust Companion Overlay: план разработки

## 0. Границы проекта (важно)

**Что делаем:** десктопное приложение-компаньон. Оно получает данные из официального
API Rust+, из лог-файла клиента и из статических справочников. Подсказки показывает в
отдельном прозрачном окне поверх игры.

**Чего НЕ делаем:**
- не читаем и не пишем оперативную память процесса `RustClient.exe`, не открываем к нему handle;
- не внедряем DLL и не перехватываем DirectX/Present;
- не ищем способов скрыться от Easy Anti-Cheat.

Почему так:
1. Если читать память игры, чтобы видеть то, чего не показывает интерфейс (игроков,
   лут, позиции), получается ESP-чит. Помогать с этим и с обходом античита я не буду.
2. Это ещё и бессмысленно практически. EAC работает на уровне ядра и ловит именно открытие
   handle к процессу. Бан выдаётся на Steam-аккаунт навсегда. Оверлей, который вообще не
   трогает процесс игры, античиту не интересен, и прятать ничего не нужно.

Главный принцип: **оверлей показывает только то, что игрок и так может легально узнать**
(через приложение Rust+ на телефоне, внутриигровые меню и вики). Мы просто выводим это
удобнее и считаем быстрее.

## 1. Источники данных

### 1.1 Rust+ Companion API (основной источник)
Официальный API от Facepunch, им пользуется мобильное приложение Rust+.

- **Транспорт:** WebSocket на `app.port` сервера (по умолчанию это игровой порт + 67,
  например 28015 → 28082). Сообщения кодируются в Protobuf (`AppRequest` / `AppMessage`).
- **Авторизация:** `steamId` + `playerToken`. Токен приходит push-уведомлением, когда игрок
  в игре нажимает «Pair with server» (ESC → Rust+).
- **Сопряжение (pairing):** вход через Steam на `companion-rust.facepunch.com`, затем
  регистрация FCM-клиента (Firebase Cloud Messaging), затем приём уведомлений с данными
  сервера и устройств. Готовые реализации есть в библиотеках `rustplus.js` (Node) и
  `rustplus.py` (Python).
- **Что можно получить:**
  | Запрос | Что даёт |
  |---|---|
  | `getInfo` | название сервера, размер карты, онлайн, очередь, дата вайпа |
  | `getTime` | игровое время, восход и закат |
  | `getMap` | изображение карты и список монументов |
  | `getMapMarkers` | маркеры: торговые автоматы и их товары, грузовой корабль, патрульный вертолёт, Chinook, ящики, взрывы, тиммейты |
  | `getTeamInfo` | состав команды, позиции тиммейтов, онлайн, живы или мертвы |
  | `getTeamChat` / `sendTeamMessage` | командный чат |
  | `getEntityInfo` / `setEntityValue` | смарт-устройства: выключатели, сигнализации, storage monitor (содержимое шкафа и время до распада) |
  | камеры CCTV | подписка на изображение с камер |
- **Броадкасты (push от сервера):** новое сообщение в чате, изменение команды, изменение
  состояния устройства (например, сработала сигнализация).
- **Ограничения:** у сервера есть rate limit (token bucket на IP и на игрока), поэтому
  опрашивать маркеры чаще чем раз в несколько секунд нельзя. Точные лимиты сверим по исходникам.
- **Риск:** в 2024 году Google менял протокол FCM, и сопряжение в сторонних библиотеках на
  время ломалось. Первым делом проверим, что актуальная версия библиотеки работает.

### 1.2 Лог-файл клиента (вспомогательный)
- Unity-клиент пишет вывод в лог. Путь можно задать параметром запуска Steam
  `-logFile <путь>`. Без параметра лог лежит в стандартном каталоге Unity (`LocalLow\...`),
  точное место проверим на твоей машине.
- Читаем файл на диске (tail), к процессу игры не подключаемся.
- Что там бывает полезного: факт подключения к серверу (IP:port, можно автоматически выбрать
  нужное сопряжение), отключение, часть сообщений консоли. Насколько это полезно, станет ясно
  после анализа реальных логов.

### 1.3 Статические справочники
- Рецепты крафта, стоимость рейда (сколько C4, ракет или сатчелей нужно на каждую стену и
  дверь), время переработки, таймеры событий (например, 15 минут на ящике Oil Rig после
  вызова, респаун Bradley).
- Источник: данные из файлов игры или открытые community-датасеты. Скрейпить чужие сайты без
  разрешения не будем.

## 2. Что можно вывести из этих данных (фичи)

Ниже фичи по приоритету. Всё вычисляется из данных Rust+ и справочников.

**MVP**
1. Подключение к серверу через Rust+, статус, онлайн, игровое время и время до ночи.
2. Детектор событий по разнице между опросами `getMapMarkers`: появился или ушёл грузовой
   корабль, патрульный вертолёт, Chinook сбросил ящик, вызван Oil Rig (запускается таймер),
   сбит вертолёт (маркер взрыва).
3. Уведомления в оверлее и по желанию звуком: «Cargo заспавнился», «Тиммейт умер», «Сработала
   сигнализация на базе».
4. Командный чат в оверлее с отправкой сообщений.

**Версия 2**
5. Мини-карта: изображение карты, монументы, тиммейты и события.
6. Поиск по торговым автоматам («где продают МВК-броню дешевле всего»).
7. Мониторинг шкафа: сколько осталось апкипа, предупреждение заранее.
8. Управление смарт-выключателями с горячей клавиши (турели, свет).
9. Калькуляторы рейда и крафта.

**Версия 3**
10. Автовыбор сервера по логу клиента.
11. Discord-бот или веб-панель для команды на том же ядре.
12. История вайпа: когда и что происходило на сервере.

## 3. Архитектура

```
┌───────────────────────── Компаньон (отдельный процесс) ─────────────────────────┐
│                                                                                 │
│  Rust+ client ──┐                                                                │
│  (WebSocket +   │                                                                │
│   protobuf,     ├──► Event Bus ──► State Store ──► Rules / Detectors ──► UI      │
│   rate limiter) │                  (SQLite)        (события, таймеры)    Overlay │
│  FCM listener ──┤                                                                │
│  Log tailer ────┘                                                                │
│  Static data ───────────────────────────────────────────►                        │
└─────────────────────────────────────────────────────────────────────────────────┘
          ▲                                                       │
          │ только сеть (сервер Rust+), файл лога                 │ прозрачное окно
          │                                                       ▼
     Rust-сервер                                     Рабочий стол Windows (игра в
                                                     режиме Borderless Window)
```

**Оверлей:**
- Отдельное окно с флагами `topmost + transparent + click-through`
  (`WS_EX_LAYERED | WS_EX_TRANSPARENT`). В Electron это `transparent: true`,
  `alwaysOnTop`, `setIgnoreMouseEvents(true)`.
- Игру запускаем в режиме **Borderless Window**: в эксклюзивном полноэкранном режиме внешние
  окна не видны.
- Окно игры находим по заголовку (`FindWindow`), чтобы подогнать размер оверлея. Handle
  процесса не открываем.
- Горячие клавиши через `RegisterHotKey` (показать или скрыть оверлей, режим интерактивности).

**Рекомендуемый стек: TypeScript + Electron + `rustplus.js`.**
- `rustplus.js` самая зрелая реализация Rust+, сопряжение через FCM там уже есть.
- В Electron прозрачные click-through окна делаются в несколько строк, UI пишется на
  React или Svelte.
- Альтернатива: Tauri (бэкенд на языке Rust, меньше размер бинарника), но тогда протокол
  и сопряжение придётся писать самим. Можно перейти позже, если понадобится.

**Структура репозитория (предложение):**
```
/packages
  /core        — Rust+ клиент-обёртка, rate limiter, детекторы событий, state store
  /pairing     — FCM listener и хранение токенов
  /overlay     — Electron-приложение (main + renderer)
  /data        — статические справочники (JSON) + скрипты их обновления
/tools
  /cli         — консольная утилита для отладки (подключиться, дампнуть маркеры)
```

## 5. Что нужно от тебя

1. **Подтвердить границы проекта** (раздел 0): без чтения памяти и без инжекта.
2. **Компьютер с Windows и Rust.** Мой контейнер работает на Linux. Ядро и CLI я напишу и
   протестирую здесь, а оверлей поверх игры можно проверить только у тебя. Есть вариант
   подключить твою папку проекта к этой сессии через Remote Control в приложении Claude.
3. **Steam-аккаунт с Rust и включённым Rust+.** Сопряжение делаешь ты сам: вход через Steam
   в браузере плюс нажатие «Pair» в игре. Токены (`playerToken`, учётные данные FCM) храним
   только локально, в `.gitignore`, и **никогда не коммитим и не присылаешь мне в чат**.
4. **Тестовый сервер (очень желательно).** Свой Rust Dedicated Server бесплатно ставится
   через SteamCMD, с `app.port` и `server.level` на маленькой карте. На своём сервере можно
   вызывать события командами (`spawn cargoshiptest`, `heli.call` и т.п.) и не упираться в
   rate limit чужих серверов. Альтернатива: дружественный сервер, где ты играешь.
5. **Решения:**
   - стек: Electron + TypeScript (рекомендую) или Tauri/Rust;
   - язык интерфейса: русский, английский или оба;
   - только для себя и команды или публичный релиз (от этого зависят лицензии
     справочников, подпись бинарника, автообновление);
   - какие 3–5 фич из раздела 2 нужны тебе в первую очередь.
6. **Логи клиента.** После пары сессий найди `Player.log` (или запусти игру с
   `-logFile`) и скинь фрагмент. По нему решим, есть ли в логе полезные данные.
   Перед отправкой убери из лога IP и SteamID, если не хочешь их светить.
